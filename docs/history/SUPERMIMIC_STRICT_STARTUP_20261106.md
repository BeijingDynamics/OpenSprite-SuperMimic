# Run002：严格启动包络的闭环分析与候选方案

2026-11-06，在保持原力矩、速度、位置和姿态保护的条件下，找到了一组通过
**88/88 次、每次 50 秒**闭环仿真的启动与命令配置。全部物理步的原始力矩请求
饱和计数、速度超限计数和前馈字段越界计数均为零。完整 Python 回归为
**308 passed, 33 subtests passed**。

这是仿真候选方案。没有使能电机、打开 CAN/真实 IMU、发送电机帧或替换当前部署。
新控制实现尚未完成 Jetson 实时反馈回放和时序集成验证，不能据此认定真机可走。
已验证的前进请求最高为 0.25 m/s；没有宣称原来的 0.3/0.6 m/s 或任意摇杆组合通过。

## 原事件发生在启动阶段

旧配置在启动后 2 秒内始终输入零速度命令；七个测试用例都在 1.30 秒触发同一个
左髋 pitch 事件，因此原来的 0/7 并不是七种步态各自失败。

| 量 | 旧配置在 1.30 s 的值 |
|---|---:|
| 电机位置 / 保持目标 | -0.353126 / -0.594055 rad |
| 电机速度 | -3.608626 rad/s |
| 嵌入式 Kp / Kd | 130 / 3 |
| P 项 / D 项 / 前馈项 | -31.320718 / +10.825879 / 0 Nm |
| 原始总力矩请求 | **-20.494838 Nm** |
| 该速度下的原保护包络 | **15.112922 Nm** |

目标与位置分离、速度升高后，保守力矩包络也随速度下降，最终触发保护。
总力矩包络仍使用既有速度/铭牌模型和 MIT 前馈字段范围的保守代理，
不是测功机实测的电机总输出曲线。此次没有修改它来让结果通过。

最终代码重新运行原 2 秒交接、无残余阻尼、无命令斜率限制的配置，仍精确得到
1.30 秒、-20.494838468715557 Nm 对 15.11292152833239 Nm。旧故障保持可复现。

## 启动交接与阻尼实现要一起分析

原交接是从实测初始位置到策略动作的平滑混合。把混合时间拉长，并不保证更稳：
动作长期受到初始位置约束，会压低策略需要的平衡修正，随后产生更大的恢复动作。
不交接在 0.02 秒触发保护；4/6 秒交接约 1.7 秒因机身高度/倾角失败。
1/1.5 秒交接能够跨过共同启动事件。

另一个差异是阻尼的执行方式。训练关节 Kd 经电机坐标变换后，部分电机需要
大于 3 的对角阻尼；现有执行器配置把嵌入式 Kd 限制在 3。旧实现保留该限制，
没有通过主机前馈补回被截掉的对角部分。这是训练与执行实现的差异，
不能仅凭仿真把旧实现称为程序错误。

新增可选实现保持嵌入式 Kd 上限 3，把缺失阻尼作为主机采样前馈。
令电机位置为 `m = A q + b`，则
`D_motor = A^-T D_joint A^-1`，主机实现的残余为
`D_motor - diag(clipped_embedded_Kd)`。
直接关节 Kd=5、嵌入式 Kd=3 的例子中，补偿项为 `2*(desired_velocity-measured_velocity)`。
差分关节则同时保留原有非对角耦合项。

补偿在 50 Hz 命令更新时采样并保持，不假装它是电机内部连续阻尼。
单元测试分别检查采样时刻的阻抗分解和两次命令之间的保持行为。
总 PD+前馈仍受原包络检查；另增加了独立的前馈字段检查，禁止通过 P/D 抵消
掩盖前馈字段越界。默认关闭补偿，原有调用行为保持可复现。

## 消融结果与取舍

下面前几组使用原先包含前进 0.30、转弯 `(0.30, 0, ±0.15)` 的命令；
它们与最终收敛到 0.25 的命令集不同，不能只比较通过率而忽略范围。

| 实验 | 结果 | 说明 |
|---|---|---|
| 2 s 交接 + 残余阻尼，名义时序 | 21/21，45 s | 只解决名义时序不够 |
| 同上，压力时序 | 0/21 | 共同启动事件约 1.36 s |
| 1.5 s 交接，无补偿，静态命令 | 名义 21/21；压力 16/21 | 缩短交接本身有帮助 |
| 同上，连续命令 | 名义 9/12；压力 7/12 | 单次启动通过不能替代连续动作测试 |
| 1.5 s 交接 + 补偿，静态命令 | 名义 21/21；压力 18/21 | 压力下晚期右转仍超过原力矩上限 |
| 右转命令网格 | 17/18 | 存在非单调失败，端点通过不能证明整个速度区间 |
| 最终命令集 + 斜率限制 + 1.5 s + 补偿 | **88/88，50 s** | 下述确切测试范围 |

最终候选没有重训或更换权重，配置是：

- 从实测位置向策略动作交接 **1.5 s**，启动前 **2.0 s** 保持零速度命令。
- 开启上述残余阻尼前馈，嵌入式 Kd 上限仍为 **3**。
- 平面线速度命令向量的变化率上限 **0.25 m/s²**，偏航命令变化率 **0.3 rad/s²**。
- 明确测试的请求 `(vx, vy, yaw_rate)` 为 `(0,0,0)`、`(0.15,0,0)`、
  `(0.25,0,0)`、`(-0.15,0,0)`、`(0.25,0,0.15)`、`(0.25,0,-0.15)`、`(0,-0.15,0)`。

限制请求幅度与变化率会改变可用行为，因此它们是候选运行条件，不是原模型
全速度范围已解决的证明。原始请求与斜率限制后的实际策略输入分别存储在
`raw_commands` 和 `commands` 中。少数原始目录/用例名沿用 `forward030`，
实际命令值以 JSON/NPZ 数值为准；最终录像已标注 0.25。

## 最终验证范围

闭环包括校准电机映射、并联踝机构映射、500 Hz 主机踝 PD 及交错发送、
1 kHz 非踝嵌入式 PD、50 Hz 策略/前馈和 0.5 ms 物理积分。
训练 PD 仍为约定的 500 Hz，没有改训练配置。

| 条件 | 静态请求 | 连续请求 | 每次时长 |
|---|---:|---:|---:|
| 名义：10 ms 延迟，无额外反馈延迟/响应滞后 | 21/21 | 12/12 | 50 s |
| 压力：12 ms 延迟 + 2 ms 反馈延迟 + 5 ms 一阶滞后 | 21/21 | 12/12 | 50 s |
| 压力 + 独立初态种子 404/505 | 14/14 | 8/8 | 50 s |

基础种子为 101/202/303。独立初态加入 ±0.005 rad 关节位置和机身 roll/pitch
扰动，保持关节硬范围，脚底距地 1 mm。这只是有限初态验证，不是完整硬件域随机化。
连续请求包括启动/停止、左右转弯、倒退/停止/前进、横移/停止，每 6 秒切换。
88 次总计 4400 秒物理时间，所有物理步检查原始请求，无隐藏饱和、速度超限或前馈越界。

稳定性通过不等于精确速度跟踪。例如名义时序、种子 101 的最后 5 秒：
前进请求 0.15 实测约 0.084 m/s；请求 0.25 实测约 0.171 m/s；
倒退请求 -0.15 实测约 -0.076 m/s。前进存在约 0.03–0.04 m/s 的侧向漂移。
这轮解决的是已测条件下的严格启动/持续运行，速度偏差仍需独立改进。
